Используемые технологии:  VirtualBox/VMware/Cloud, Linux(users,groups,rights), SSH 

Первым делом мы займемся настройкой доступов для пользователей. Представим, что в компании у нас появились два разработчика, которым нужен доступ на сервер. Raymond не любит вводить пароли, так как считает их панацеей, а вот John хочет заходить только пользуясь паролем. В конце концов нам нужно дать большие привилегии Raymond. В Linux у каждого файла есть определенный набор прав, который применяется к тому или иному пользователю. Например John может создать файл и дать запрет на какое-либо чтение/изменение файла пользователю Raymond. С этим тебе и предстоит разобраться, так как у John и Raymond вышли относительно натянутые отношения. 

В Linux достаточно много built-in утилит, которые позволяют настраивать систему. Для создания пользователей можно использовать команду useradd.

Пример создания пользователя, используя useradd:
sudo useradd -m -d /home/givi -g users -s /bin/bash givi

В данном примере флаг -m позволяет задать домашнюю директорию для пользователя Givi. Флаг -g указывает группу для нашего нового пользователя, а -s интерпретатор команд для пользователя - /bin/bash.

sshd_config

Файл используется для конфигурации различных параметров сервера:

    Настройка доступа: используется для определения какие пользователи и IP-адреса имеют доступ к серверу и какие методы аутентификации могут использоваться.

    Настройка безопасности: используется для конфигурирования различных мер безопасности, таких как ограничение количества неудачных попыток входа и ограничение методов аутентификации.

    Настройка перенаправления: используется для настройки того как клиенты будут перенаправлены после аутентификации, например запуск какой-то программы или соединения к другому серверу.

С помощью этого файла тебе и предстоит настроить параметры доступа для пользователей. А помогут директивы PasswordAuthentication; PubkeyAuthentication.

Пример с пользователями Givi, Selin с допуском аутентификации по паролю:
Match User givi, selin
  PasswordAuthentication yes

При подключении с использованием SSH ключа клиент должен иметь сгенерированную пару приватный ключ/публичный ключ, из которых приватный ключ будет находиться у себя на рабочей машине, а публичный ключ будет находиться в файле authorized_keys.

authorized_keys это файл, который содержит публичные ключи для аутентификации SSH. Когда клиент пытается подключиться к серверу через SSH, сервер проверяет наличие клиентского публичного ключа в этом файле. Если ключ найден, то сервер разрешает доступ клиенту.

Этот файл обычно находится в домашней директории пользователя в папке ~/.ssh/authorized_keys. Каждая строка в этом файле содержит один публичный ключ.

Теперь перейдем к интерпретаторам.

Интерпретатор в Linux - это программа, которая исполняет команды, введенные пользователем в командной строке или в скрипте. Интерпретаторы исполняют команды по одной за раз, а не компилируют их в машинный код заранее.

Некоторые из наиболее распространенных интерпретаторов в Linux:

    bash: это наиболее распространенный интерпретатор в Linux. Он используется в качестве интерпретатора по умолчанию в большинстве дистрибутивов Linux.

    sh: это интерпретатор командной строки POSIX, который также распространен в Linux. Он используется в качестве совместимого интерпретатора для скриптов, написанных для других систем.

    zsh: одна из современных командных оболочек UNIX, использующаяся непосредственно как интерактивная оболочка, либо как скриптовый интерпретатор.

    nologin: при назначении ее пользователю блокируется любая попытка входа под данным пользователем, очень удобно при создании пользователей под различные сервисы, а также является плюсом в рамках безопаности. 

    и другие.

Скорее всего у тебя возник вопрос, зачем столько интерпретаторов? На самом деле это достаточно хороший вопрос, ввиду того что интерпретаторы разрабатывались под разные нужды и имеют разный функционал. В некоторых дистрибутивах присутствует только sh. В других присутствует sh и bash. Также очень полезно назначать интерпретатор nologin, который блокирует любую попытку войти под текущим пользователем. В любом случае полезно уметь менять базовые интерпретаторы для пользователей.

Пример смены оболочки на /bin/sh для пользователя Givi:
sudo chsh -s /bin/sh givi

Посмотреть текущую оболочку/интерпретатор для пользователя можно в файле /etc/passwd.

Как работать с правами файлов/каталогов? Сначала выведем их, для этого введем команду ls -l.

Тык

Мы получили список файлов/каталогов в текущей директории, а также права доступа.

    Первая группа из трех символов(rwx) обозначает права доступа владельца файла или папку (u - user).

    Вторая группа из трех символов(rwx) обозначает права доступа на файл или папку для системной группы (g - group).

    Третья группа из трех символов(rwx) обозначает права доступа на файл или папку для всех остальных (o - other).

    У каталогов(подсвеченных синим) есть нулевой символ(d). 

Допустим, мы являемся владельцем файла с именем docker-compose.yml с прошлого скриншота и хотим установить его разрешения так, чтобы:

    обладатель (*u*ser) мог читать (*r*ead), писать (*w*rite) и выполнять (e*x*ecute) его;

    члены группы (*g*roup) могут прочитать (*r*ead) и выполнить (e*x*ecute) его;

    а также другие (*o*thers) могут только читать (*r*ead) его.

Сделаем это с помощью chmod - это команда, которая предназначена для изменения прав доступа к файлам и каталогам.  Использовать данную команду можно двумя путями.

Численно. chmod 754 docker-compose.yml - здесь цифры 7, 5 и 4 каждая по отдельности представляют разрешения для пользователя, группы и других в этом порядке. Каждая цифра представляет собой сумму/комбинацию чисел 4, 2, 1 и 0:  

    4 означает «читать»,

    2 означает «записать»,

    1 означает «выполнить»,

    0 означает «нет разрешения».

Символьно. chmod u=rwx,g=rx,o=r docker-compose.yml - здесь буквы u, g и o обозначают «пользователь», «группа» и «другое». Знак равенства («=») означает «установить права доступа именно так», а буквы «r», «w» и «x» означают «чтение», «запись» и «выполнение» соответственно. Запятые разделяют различные классы разрешений, и между ними нет пробелов.

Чекпоинты: 

    Поднять ubuntu на VirtualBox/VMware/Cloud. Создать там пользователей Raymond и John. 

    Raymond должен заходить только по SSH ключу на инстанс. А John должен каждый раз вводить свой пароль при попытке зайти на инстанс и не иметь возможности зайти по ssh ключу.

    Raymond должен иметь доступ к sudo, а John не сможет использовать его. 

    Из под пользователя Raymond создать документ, используя права доступа сделать так, чтобы пользователь John не смог редактировать содержимое документа, но смог его прочитать. Из под пользователя John создать shell скрипт(с любой командой) и дать возможность запускать его пользователю Raymond. 

    Поменять интерпретатор по умолчанию пользователю John(сделать, чтобы был bash). Создать нового пользователя так, чтобы у него сразу был интерпретатор sh по умолчанию. 

    Добавить нового пользователя в группу пользователя John, проверить, сможет ли он запускать созданный ранее shell скрипт. 

    Создать на своей хостовой машине файл, после чего прокинуть его на инстанс с помощью scp. 

    Используемые команды должны быть записаны в отдельный файлик.
