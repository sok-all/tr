Используемые технологии:  Linux, Systemd, Cron

Настало время сдружиться с демонами, буквально на небольшой период времени 🙂 Но сначала про процессы. Ознакомься с данной статьей самостоятельно Processes. Кратко говоря процессы в Linux - это программы, которые выполняются в системе. Каждый процесс имеет уникальный идентификатор (PID - process id). Всеми этими процессами управляет systemd(system daemon) - представляет собой менеджер системы и служб, который выполняется как процесс с PID 1 и запускает остальную часть системы.

`systemd`

Для того, чтобы описать как процесс будет отслеживаться, контролироваться и управляться системой используются systemd units. Проще говоря это службы, описанные конфигурационными файлами, например unit с именем example.service:
```
[Unit]
Description=Example service that starts bash script

[Service]
ExecStart=/usr/local/bin/example.bash

[Install]
WantedBy=multi-user.target
```

В данном примере unit указывает systemd запустить скрипт example.bash при запуске службы. Поле Description содержит человекочитаемое описание службы, а поле WantedBy указывает, что служба должна быть запущена как часть цели multi-user.target(если интересно, что такое multi-user.target - тык). Запуск самой службы осуществляется командой systemctl start example.service.

Ты еще не раз встретишься с командой systemctl, она отвечает за:

    запуск, остановку и перезапуск служб

    проверку статуса служб

    включение или отключение служб при запуске системы

    управление конфигурацией служб на уровне системы

    просмотр и манипуляцию с журналами служб на уровне системы

Чтобы посмотреть статус службы, например systemd-logind.service, которая отвечает за управление сессиями пользователей, используется команда  systemctl status systemd-logind.service. 

А теперь обобщим.

Systemd unit- это сервис, демон, который управляется системным менеджером systemd. Они могут использоваться для автоматического запуска, остановки и перезапуска программ и служб, а также для настройки их зависимостей. 

Опять же, мы не будем писать службу, если нам нужно запустить какой-то скрипт или программу, которая должна отработать только сейчас без какого-либо контроля со стороны системы, а ведь запущенная программа это тоже процесс. Допустим нам нужно сделать ping 8.8.8.8, чтобы проверить доступность сети. Мы просто впишем эту команду в CLI и подождем ответа. Если ты уже попробовал вписать эту команду в терминал, то заметил, что в данный момент консоль недоступна. А что, если нам нужно, чтобы процесс запустился в фоновом режиме? Итак:

    Запуск процессов на переднем плане в Linux.

    Запуск процессов в фоновом режиме в Linux осуществляется с помощью символа "&" после команды. Например: ./some_program.sh &. Если хочешь проверить работоспособность, напиши зацикленный shell скрипт, либо начни скачивание какого-либо файла отсюда 

      с помощью wget. Например wget http://ipv4.download.thinkbroadband.com/512MB.zip &.

Для просмотра фоновых процессов в Linux используется команда jobs. Допустим ты захотел снова вернуть процесс со скачиваем файла на передний фон. Смотрим, что выдает нам jobs:

Тык

Видим ID нашего процесса - 1, пишем fg %1 и бинго. fg %ID - команда, которая возвращает фоновый процесс на передний план.

Для отслеживания процессов есть достаточно много команд - ps, top, htop. Сам ps выводит информацию о процессах статически, top - в режиме реал-тайм. Если какой-то процесс слишком уж тебе не понравился, можешь найти его PID используя ps, а затем удалить его командой kill -9 PID.

Переключимся на отслеживание загрузки самой системы. В случае, если твой сервачок начал нагибаться и еле выдает ответы на команды, есть небольшая вероятность, что у тебя майнер… Или просто система загружена процессами. Торвальдс Линус для таких случаев создал Load Average, а вообще не он. Данная метрика показывает среднюю нагрузку на систему. Ее текущий показатель ты можешь посмотреть с помощью команды uptime, а также найти в выводе w, top.

Поля содержат значения средней загрузки системы за последние 1, 5 и 15 минут соответственно. Показатель load average: 2.21, 2.29, 2.23 говорит, что в течение последних 5 минут нагрузка в среднем была больше, чем за 15 минут, а наименьшая нагрузка была за последнюю минуту. Соответственно, если показатели выстроены так load average: 2.70, 2.50, 2.20, то нагрузка на систему возрастает.

cron

{{Cron }}- это системная утилита в Linux, которая позволяет запускать программы и скрипты в определенное время по расписанию. Она может использоваться для автоматизации рутинных задач, таких как обновление баз данных, резервное копирование файлов и т.д.

Пример написания cronjob. Открываем cron table командой crontab -e . Вставляем скрипт:
0 3 * * * /path/to/script/backup.sh

По итогу имеем cronjob, которая запускает backup.sh скрипт каждый день в 3:00 AM. А теперь подробнее: линия стартует с минут(0-59), затем часов(0-23), потом дня месяца(1-31), потом самого месяца(1-12) и наконец дня недели(7). Выглядит это как-то так:
минута час день_месяца месяц день_недели название_скрипта
